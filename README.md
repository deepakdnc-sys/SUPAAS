# Swarnkar Garba Mahotsav 2026 — Digital Pass Website

A GitHub-ready website project with visitor booking, payment UTR + screenshot submission, downloadable QR tickets, UTR-based retrieval, admin approval and booking controls, manual admin passes, and a gate scanner with cumulative entry tracking (maximum 4 people per pass).

## Stack
- Frontend: HTML, CSS, vanilla JavaScript
- Backend/database/storage: Supabase
- QR display: `qrcode` browser library
- QR scanning: `html5-qrcode` browser library
- Hosting: GitHub Pages, Netlify, or Vercel (HTTPS required for camera scanning)

## Important security note
The requested passwords `ADMIN` and `admin` are weak. This project does **not** hard-code them into public frontend JavaScript. Set them as Supabase Edge Function secrets (`ADMIN_PASSWORD` and `SCANNER_PASSWORD`) so visitors cannot read them from the website source. Change them before going live. The Edge Functions check the password on the server. For stronger production security, replace shared passwords with individual staff accounts and rate limiting.

## Setup
1. Create a Supabase project at https://supabase.com.
2. In Supabase SQL Editor, run `supabase/schema.sql`.
3. Create a private Storage bucket named `payment-screenshots` (or run the SQL comments/instructions in `schema.sql`). The upload is handled through the server function.
4. Install Supabase CLI, log in, and link your project:
   ```bash
   npm install -g supabase
   supabase login
   supabase link --project-ref YOUR_PROJECT_REF
   ```
5. Set secrets (replace values; the defaults below match your requested initial passwords):
   ```bash
   supabase secrets set ADMIN_PASSWORD=ADMIN SCANNER_PASSWORD=admin UPI_ID=8385963066@upi SUPPORT_PHONE=8385963066
   ```
   **UPI ID note:** `8385963066` is a mobile number, not a universally valid UPI ID. Ask the recipient which UPI handle is registered (for example `number@bankname`) and set `UPI_ID` to that exact handle. The website displays the supplied number and creates a UPI intent using the configured handle.
6. Deploy Edge Functions:
   ```bash
   supabase functions deploy public-api
   supabase functions deploy staff-api
   ```
7. Edit `config.js` and set your Supabase project URL and **anon/publishable key**. Never put the service-role key in frontend code.
8. Host the contents of this folder on a static HTTPS host. For GitHub Pages, push these files to a repository and enable Pages in repository settings.
9. Open the site and test with a small test payment before public launch.

## Booking and entry workflow
- Visitor fills name and mobile, pays ₹200 per pass via UPI, enters UTR/reference number, and uploads a payment screenshot.
- One booking QR supports up to 4 people total. The amount is ₹200 per person, so booking 1–4 people costs ₹200–₹800.
- A ticket is created immediately but stays **PENDING** and cannot be scanned for entry until an admin approves it.
- Visitors can retrieve a ticket with their UTR number and mobile number.
- Admin reviews the screenshot, approves/rejects a payment, toggles booking availability, deletes one booking or all bookings, and creates a manual pass by name.
- Gate staff log in, scan a QR, select 1–4 entrants, and the backend rejects inactive, unknown, or over-limit tickets. Entry count is cumulative and cannot exceed the approved pass capacity.

## Operational notes
- QR tickets contain an opaque ticket token, not personal details.
- Screenshot URLs are private signed URLs generated by the backend.
- The supplied mobile number is shown as Help & Support: Deepak Soni, Moti Chowk, Jodhpur, 8385963066.
- A QR ticket is not proof of payment approval. Gate validation always checks the database.
- Keep Supabase backups enabled. Deleting all records is irreversible.
